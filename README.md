# 潮位报文归集台

港务水文组收到各潮位站的定长报文。归集员把一批报文贴进来，系统按当天钉住的去重键解析、去重，能落库的写入归集表；列数不对、潮位越界、质量旗非法的行进未接纳，键里缺站码或时刻的行进冲突队列。

## 去重键

去重键只有两种组成，选定后当天钉住，不得更换：

| 键名 | 组成 |
|------|------|
| 站时键 | 站码 + 观测时刻 |
| 站时旗键 | 站码 + 观测时刻 + 质量旗 |

- 键设置没保存完，不能开始归集。
- 归集时携带的键必须与当天键设置一致；不一致写「去重键不符」，这批整批不落库。
- 两个归集员同时用不同键撞同一行时，按站与时刻加锁排队，只采纳与键设置一致的那一次，另一次记「键争用」。
- 键里缺站码或观测时刻的行进冲突队列；站时旗键下缺质量旗也进冲突队列。

页面左侧读出当前用的是哪一种键；键列表显示键名、键组成和冲突行数，点开详情展开被挡住的组合。

| 层 | 选型 |

| 数据库 | PostgreSQL 16 |

## 启动

```bash
cd projects/01-tide-telegram-intake
docker compose up --build
```

健康检查：`GET http://localhost:8211/api/health`

## 种子数据

| 批次 | 结果 |
|------|------|
| 吴淞口 11-12 早班 | 三行都已归集 |
| 外高桥 11-12 错报 | 一行新站落库，一行时刻重复，一行站码不合法被挡下 |

报文每行四段，用竖线分开：站码、十二位时间、潮位厘米、质量旗。质量旗 A 是实测，M 是插补，B 是可疑。

## 接口

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/dedup-key` | 读出当前去重键 |
| PUT | `/api/dedup-key` | 保存并钉住当天键组成 |
| GET | `/api/dedup-keys` | 键列表：键名、键组成、冲突行数 |
| GET | `/api/dedup-keys/{date}` | 键详情：被挡住的组合 |
| GET | `/api/conflicts` | 冲突队列 |
| POST | `/api/batches` | 归集一批，可带 `key_parts` 以示携带的键 |
